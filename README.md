# Креатив

Небольшой стол для креативного отдела. Байер пишет бриф, креативщик берёт его и сдаёт ссылки, байер принимает работу или возвращает на правки, руководитель смотрит доску и цифры.

Интерфейс и демо-тексты на русском. Код на английском. Техническое задание — в [TECHNICAL_SPEC.md](TECHNICAL_SPEC.md).

## Запуск

Демо запускается через Docker. Из корня репозитория:

```sh
docker compose up --build
```

Откройте http://localhost:8080. При первом старте база мигрирует и загружает демо. Postgres и API снаружи не опубликованы. Браузер ходит только на порт 8080.

Чтобы стереть демо-данные и засеять их заново:

```sh
docker compose down -v
docker compose up --build
```

## Локальная разработка

Файл для разработки публикует Postgres на `127.0.0.1:5432`. API и веб остаются на хосте, поэтому cookie по-прежнему идёт через один origin.

```sh
docker compose -f docker-compose.yml -f docker-compose.dev.yml up db -d
cp .env.example apps/api/.env
bun install
bun run dev:api
bun run dev:web
```

Веб открывается на http://localhost:5173 и проксирует `/api` на API.

```sh
bun test
bun run test:scenarios
bun run test:e2e
```

`bun test` проверяет чистые правила, база ему не нужна. `test:scenarios` поднимает API на отдельной базе `desk_test` через опубликованный порт Postgres, демо-данные при этом остаются на месте. `test:e2e` — один проход в браузере, ему нужно запущенное демо на http://127.0.0.1:8080.

## Решения

**Только ссылки.** Бриф и сдача — списки адресов `http` и `https`. Хранилище файлов добавило бы том, лимит размера и протокол загрузки продукту, которому нужны только адреса. Список ссылок позже можно заменить файлами, не меняя того, кто берёт задачу, сдаёт и принимает. Любая другая схема, в том числе `javascript:`, отклоняется.

**Команды.** Клиент читает два готовых документа: карточку на доске и страницу задачи. Поля он не выбирает, подписок нет. Каждое действие — команда с путём и проверкой роли, поэтому API — короткий список таких команд под `/api`. Граф повторял бы документы, которые сервер и так собирает.

**Доска без перетаскивания.** Колонки показывают, где лежит работа. Смена статуса — действие на задаче с проверкой роли, поэтому карточка не может перескочить проверку. Подпись на доске это прямо говорит, и колонки не выглядят недоделанными.

**Кто видит задачу.** Пул новых задач общий для всех байеров. После того как креативщик её берёт, задачу видят только он, автор и руководитель. Байер проверяет только свои задачи. Руководитель читает все задачи и аналитику. Взять, сдать или принять он не может.

**Время.** Сервер записывает создание, момент взятия, каждую сдачу и приёмку. Одну метку сдачи, которую следующий круг перезаписал бы, он не хранит. Длительность — это приёмка минус взятие, подпись на странице: «От взятия в работу до приёмки». В промежуток входит ожидание проверки. Число можно пересчитать по двум меткам на странице. Отдельные часы «чистой работы» с этими метками не сошлись бы, поэтому их нет. Задача просрочена, когда дедлайн прошёл и она ещё не готова, в том числе если её никто не взял.

**Кредиты AI.** Креативщик выбирает сервис из засеянного каталога и вводит положительное число кредитов. Записи остаются на задаче через правки и проверку, их не редактируют. Сумма — отчёт о том, что люди ввели, а не пересчёт в деньги. Новый сервис добавляется в данные, а не свободным текстом, поэтому разбивка у руководителя остаётся по группам.

**Один origin.** Клиент вызывает относительный `/api`. Nginx и прокси Vite передают этот префикс дальше, остальные пути отдают SPA. `GET /health` остаётся на контейнере API и наружу не публикуется. Сессия — cookie `httpOnly` с `Path=/`, без `Domain` и без `Secure`: демо работает по HTTP. Токен несёт идентификатор пользователя, а сам пользователь каждый раз читается из базы. `Secure` включают, когда перед сервисом стоит TLS-прокси.

**bun и Nest.** bun ставит зависимости, запускает скрипты и стартует собранный API. Nest собирается своим компилятором: внедрение зависимостей требует метаданные декораторов, а транспилятор bun их не выдаёт. Локально Nest компилирует код, процесс запускает `bun dist/main.js`. Пароли хешируются через bcryptjs, поэтому образу не нужно нативное расширение.

**За рамками.** Подписки, уведомления, регистрация, правка задач, перетаскивание и библиотека графиков. Демо рассчитано на десятки задач и отдаёт их все сразу. Тот же образ на хосте — выкладка на один порт. Манифест платформы репозиторий не добавляет. `JWT_SECRET` в `.env.example` — секрет только для демо. Если переменной нет, процесс завершается и сам секрет не придумывает.

## Инструменты ИИ

План и реализация сделаны в Cursor одним агентом, Grok 4.7. Агент написал план, в той же сессии его проверил и затем реализовал по этому плану. Позже тот же агент заменил транспорт GraphQL на REST-команды под `/api`. Второму агенту часть работы не отдавалась, параллельного разделения на планировщика, кодера и ревьюера не было.
